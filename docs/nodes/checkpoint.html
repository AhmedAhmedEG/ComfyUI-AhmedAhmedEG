MiniMax H3 Load Take Checkpoint

Loads a complete saved take from a project’s server-side cache.

Checkpoints4 outputs

Use it when: Use it to resume or branch from an already completed shot.

In plain language

A take is one generated version of a shot. This loads a complete take saved in this pack’s server-side cache, including the compressed generation result needed by continuation workflows. It is not a diffusion-model loader.

Your first use: Choose the project ID, clip ID and take ID of a completed saved take. These IDs identify cache entries; they are not the friendly shot name. Use the outputs in a continuation graph. Importing a workflow JSON alone does not bring those cache files with it.

Connections

checkpoint → Master continuation
frames / audio → export nodes if you only want the saved media

How it works

  • latest selects the current take for clip_id. An explicit take UUID selects that historical generation from the manifest.
  • Loads the saved latent, decoded frames and audio. Fails if any required artifact is missing or unreadable.
  • Returns a continuation object plus separate media and latent outputs; it does not generate a new take.

How to use it

  1. Find the project ID, shot ID and optional take UUID in the Master’s saved-take tools.
  2. Enter those values and load the checkpoint.
  3. Connect checkpoint to another Master continuation input to branch or continue.

Settings and controls

Initial values come from the node’s declared UI schema. The starter can use different values. Required settings have widgets; they do not all require cables. Runtime model/sampler choices depend on your installation.

Limits and troubleshooting

  • Project and shot IDs are cache identifiers, not the shot’s display name.
  • Cache files must remain on the same server or be restored. Portable reference archives exclude heavy generated-take storage.
