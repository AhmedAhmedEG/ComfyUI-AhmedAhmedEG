MiniMax H3 Reference Pack (Pool)

Pools graph-supplied references for local selection on individual Master clips.

References and prompts1 output

Use it when: Use this as the sole asset source for Master clips. Connect media loaders, then choose the compatible subset for each clip.

In plain language

This collects images, video frames, audio and reference bundles from graph connections into a shared shelf. The Master can choose items from that shelf for each shot.

Your first use: Connect media to the pool, then connect ref_pack to the Master’s ref_pack input. In the Master, use Refresh pool beside the reference list if upstream files or names have changed and assign the desired items to a shot. Adding media to the pool alone does not mean every shot will use it.

Connections

Reference Pack ref_pack → Master ref_pack
Earlier pool ref_pack → next pool ref_pack_optional

One media pool, many independent shot selections

A Reference Pack is a catalog of graph-supplied media. It does not generate, encode or automatically apply every asset. Its output connects to Master.ref_pack; each Master shot stores the IDs it selects. Thus one character image can be available throughout a project while only some shots use it. Names are labels for you, not instructions to load a file.

Each node offers image_1…image_4, video_1…video_2, audio_1…audio_2 and refmod_1…refmod_2. Unconnected IMAGE/AUDIO inputs are omitted from the pack. A RefMod string is omitted when blank or None. Entering video_1_name without connecting video_1 does not create a fake video. There is no Master upload button competing with this catalog.

Media types and optional names

An IMAGE is a tensor batch in [frames, height, width, channels] order. For an image slot it usually comes from Load Image. A video slot is also IMAGE because the loader supplies decoded frames; it is not an MP4 filename or native VIDEO container. An AUDIO object carries waveform and sample_rate. Use installed media loaders to supply those outputs. A RefMod is a supported H3 reference-model path/name, normally in models/refmods, not an ordinary diffusion MODEL or Turbo LoRA.

For each slot, the matching …_name is optional. Use labels such as Alice, Red coat, Room layout or Voice sample. Whitespace is trimmed; an empty name falls back to the stable slot ID. Names do not change image pixels, native reference-token syntax or RefMod weights. The execution pack carries media data and metadata; it does not copy GPU tensor bytes into the workflow JSON.

Chaining and stable identities

Connect an earlier pack to ref_pack_optional. Existing rows are inherited, then this node adds its occupied slots. The first pack uses IDs such as image_1; later packs use prefixes such as p2_image_1 to avoid collisions. The internal row records id, slot_id, alt_id, pack_index, name, type and data. Rearranging the graph's chain can change those identities, so keep a stable chain after assigning shots.

Load Image: Alice ─→ Pool A.image_1   image_1_name = Alice
Load Image: Room  ─→ Pool A.image_2   image_2_name = Room
Pool A.ref_pack ─→ Pool B.ref_pack_optional
Load Audio: Voice ─→ Pool B.audio_1  audio_1_name = Voice
Pool B.ref_pack ─→ Master.ref_pack

The pool can grow by chaining, but a single generated shot still has task/model reference limits. Pool capacity and per-shot conditioning capacity are different constraints. The editor discovers connected graph references without first running the entire generation pipeline; Refresh pool beside the reference list refreshes that view after changing loaders/names.

Assigning and troubleshooting

  1. Connect two real images and give them useful names.
  2. Choose REF2VA on a Master shot; select only the assets for that shot.
  3. Read the shot's Picture-token labels and write a prompt using those positions.
  4. For a different shot, choose its own subset. Changing the name helps identification but does not approve a take.

A newly installed loader may supply pixels successfully while its file metadata is not recognizable to the editor's graph-discovery code. In that case a missing thumbnail is different from missing execution data. Inspect the connected socket/loader and refresh references. Audio and video previews need actual resolvable source media; static placeholder rows must not be treated as evidence of a connected asset.

Implementation: pool schema and IDs, reference loading/editing, graph discovery and token buttons.

Video timing and paired sound

video_1 and video_2 take IMAGE frame batches, which have no intrinsic frame rate or soundtrack. Supply their actual loader output rate using video_1_fps/video_2_fps (24 by default, 1–240 allowed). The pack converts frame timing to H3's 24 fps by selecting source indices floor(i × source_fps / 24), clamped to the available batch; the output frame count is round(source_count × 24 / source_fps). This is frame resampling, not motion interpolation.

Optional video_1_audio/video_2_audio sockets attach the corresponding loader soundtrack to a video entry. They do not create selectable standalone assets. Reference generation passes them through ref_video_audios; existing-video and edit clips trim them with the selected source range. Without these connections a pixel batch is silent. Standalone audio_1/audio_2 still create separate selectable audio references.

Every clip selects from this same injected pool. Existing Video and Edit Video allow one video only; image modes show images only with one/two-image limits; text mode shows none; REF2V/RV2V enforce their per-type and total caps. The backend checks again, including RefMod kinds and reference durations. Unsupported or missing assignments produce errors before sampling.

Pack-owned asset preparation

The asset panel is the current name/editing surface. Old name widgets remain serialized for compatibility but are hidden. Connected slots or uploaded files appear with role and description, crop coordinates, exposure/contrast/saturation, trim seconds, waveform handles and scaling. Drag a rectangle on a file preview to crop normalized coordinates. Video can expose both streams, video only, audio only, or one picked frame. Trim happens before frame selection; Picked Frame time is relative to that trimmed range. Add Current Frame creates a new server image asset. Files are uploaded only here, then clips select existing pack IDs.

Execution applies these settings to copies and preserves stable IDs. It resamples graph video to 24 fps before trim, keeps paired sound aligned, and rejects empty ranges or audio-only video without sound. File-backed previews/Forge can reconstruct the recorded edits. Arbitrary procedural graph transformations cannot be reconstructed from a loader filename alone; use native tensor graph connections for those. RefMod Library connects to refmod_library and owns its descriptions/strengths.

Compatibility and ownership in 1.6

Prompt Cast is a collapsed per-image section. Assign up to three Character numbers, screen position, visual retention and Include/Ignore for the prompt writer. These annotations do not remove a clip reference from model conditioning. Clip reference selection remains the sole owner of which assets reach the video model. Several image references may share a Character number; ordered numbers and Left-To-Right describe several characters in one reference.

People boxes

Open Prompt Cast and enable Edit People Boxes. Draw on the original picture; drag a rectangle to move it and its yellow corner to resize it. Renumber or remove each person below the picture. Coordinates remain normalized to the original file independently of media cropping. Box drawing and image cropping use separate edit modes. Up to 32 boxes are supported.

Find People uses a configured Prompt Forge vision provider selected in Vision Reader. Proposed boxes can be edited before Use Detected Boxes replaces the saved boxes. Discard leaves the saved boxes intact. Cancel Vision Request uses the shared token/stream cancellation path. File-backed image input and a functioning vision provider are required.

Execution summary

  • Adds up to four image inputs, two video-frame batches, two audio inputs and two RefMod names per pack.
  • ref_pack_optional inherits an earlier pool. Chained packs receive distinct identifiers so slots do not collide.
  • Pooling makes assets available; the Master’s shot selections decide which assets enter each shot.

How to use it

  1. Connect reference media to the matching sockets.
  2. Chain pools through ref_pack_optional if more graph inputs are needed.
  3. Connect ref_pack to Master ref_pack, use Refresh pool beside the reference list if upstream files or names have changed, and assign assets to the intended shot.
  4. Give connected references optional names such as Alice or Courtyard. Only connected items are listed; assign them to a shot to show their prompt tokens.

Limits and troubleshooting

  • The pool can grow through chaining, but each shot still obeys native limits: 9 images, 3 videos, 3 audios, 12 combined.
  • A video input is an IMAGE frame batch. RefMods are names/paths or bundles, not newly trained models.
  • Reference Roles accepts multiple checked roles on one image, such as Character, Place and Style. Forge preserves each role alongside assigned character definitions; these are writer instructions, while clip type and asset selection control generation inputs.
  • Prompt Cast owns normalized people boxes. Enable Edit People Boxes to draw, move, resize, renumber or remove up to 32 boxes on the original file picture. Find People uses a selected Forge vision provider and returns editable proposals; Use Detected Boxes is explicit. This changes writer metadata, not model reference selection.
