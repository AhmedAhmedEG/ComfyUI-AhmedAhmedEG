MiniMax H3 Prompt Forge Draft

Asks a local or server-accessible language model for a structured prompt draft.

References and prompts2 outputs

Use it when: Use it to draft several shots before manually accepting them.

In plain language

This asks a language model to write a structured shot draft from your instructions. A draft is a proposal you review before it changes the timeline. It does not generate the video.

Your first use: Connect a loaded local prompt model, or configure a supported language-model server. Write a short instruction such as “three shots of a robot entering a greenhouse.” Review the returned draft before applying it. Keep language-model memory use in mind alongside video generation.

Connections

Local Prompt / Vision Model → generator (local backend)
draft → Review / Apply Prompt Draft draft

How it works

  • Reads the timeline snapshot and instruction, requests shot_count draft shots, and records the source context.
  • Optional images are encoded for a provider that supports vision. No video generation occurs.
  • Returns an editable draft object and review_json text; the draft is not applied automatically.

How to use it

  1. Supply a timeline snapshot and describe the intended scenes in instruction.
  2. Choose local with a connected generator, or configure an Ollama/compatible endpoint and model.
  3. Inspect review_json, then connect draft to Review / Apply Prompt Draft.

Limits and troubleshooting

  • Provider requests originate from the ComfyUI server. localhost refers to that server.
  • Graph api_key fields can be saved in workflow JSON. Stale drafts are rejected on application if the source context changed.
  • Do not wire a Master output back into that same Master through a cyclic draft graph; use an independent snapshot or the editor draft flow.
