An LLM drafts authoring data; H3 generates the movie

Prompt Forge sends a timeline context and your instruction to a selected language-model provider, parses its answer into a constrained shot draft and returns that draft for review. It does not call the video sampler, validate a generated take, connect references or automatically apply the answer to the Master. Connect its draft to Review / Apply Prompt Draft. Drafting and review are configured only in these connected nodes.

timeline is current authoring JSON. instruction describes the shots you want drafted. shot_count requests an exact number from 1 to 100; it is neither seconds nor model context length. The system request asks for JSON with prompt, duration and type fields while preserving supplied context/reference identities. A model can still fail the requested format; parsing/validation is mandatory.

Local, Ollama and compatible HTTP providers

endpoint is evaluated on the ComfyUI server. On a remote installation, localhost:11434 means the remote host/container, not your laptop. For a compatible service whose base includes /v1, enter that base; the implementation appends /chat/completions. model_name must be a provider-known name, not the H3 diffusion checkpoint. The HTTP path uses a timeout and propagates provider/format failures.

Optional images supplies up to twelve IMAGE frames for a vision-capable provider. The node clamps pixels, converts to PNG, limits image size to 1024 and sends base64 image content in the backend's supported message shape. Selecting a text-only LLM does not make it understand images. Supplying images to an external provider transmits those images to that configured endpoint; this node is not merely inspecting them locally.

Draft contract and restrictions

{
  "context_key": "fingerprint of the supplied timeline context",
  "count": 2,
  "shots": [
    {"prompt": "A person walks toward the window", "duration": 5, "type": "T2VA"},
    {"prompt": "The person turns back toward camera", "duration": 5, "type": "T2VA"}
  ]
}

The parser normalizes supported task aliases, checks finite valid durations and checks exact shot count. It accepts only authoring fields prompt, duration and type. A response cannot invent file paths, alter ref_ids, unlock a source clip, select an arbitrary checkpoint/model override or mark a take validated. Those fields belong to explicit project authoring and execution, not model-generated authority.

draft is MMX_PROMPT_DRAFT for the apply node. review_json is a readable STRING representation for inspection. They are not CONDITIONING or finished video. The context_key permits the apply step to reject a draft based on an older/different timeline.

Drafting two shots without losing references

  1. Supply the current timeline and an instruction such as “Draft two five-second shots of the same person approaching a window; maintain appearance and soft room ambience.”
  2. Set shot_count 2 and select a working provider. Test a small draft before a long storyboard.
  3. Read review_json: inspect task types, duration and reference-token text.
  4. Apply only after review. Replace preserves relevant existing per-shot assets/overrides for matching positions; Append adds new authoring shots that still need your explicit reference assignments.

If a draft fails, inspect HTTP reachability, model availability and the returned JSON before blaming H3. If a reference is absent from supplied context, do not assume the provider can know it from an unrelated pool name. The apply-stage context check and explicit reference assignment remain necessary.
