A second latent stage before RGB decoding

Refine receives its configuration through Master.refine. After first-pass sampling, the Master can resize/refine the sampled audiovisual latent and only then decode it into visible frames. The configuration node itself returns a dictionary. enabled=false bypasses the stage without requiring you to remove its cable. Refinement can change faces, textures and motion; it is not a lossless enhancement filter.

Global and sampler backends

backend=global delegates to the consolidated DaSiWa H3 tiled-upscale engine. It coordinates spatial tiling, temporal chunking, memory budget, external schedules, precision and continuation context. backend=sampler uses the shared sampling/interpolation path. These choices are implementations of the refinement stage; they do not select FL2VA versus REF2VA.

With global refinement, memory_budget_mb is an upscaler working-memory budget; zero selects its automatic/default behavior. It is not a global GPU allocation ceiling for ComfyUI. upscale_precision selects auto, bf16, fp16 or fp32 for supported upscaling operations. Lower precision can reduce working memory but does not guarantee compatibility with every device. The sampler backend does not consume these global-engine budgeting/precision controls.

Steps, strength, passes and models

steps is the refinement schedule's step count, separate from Director Settings' first pass. denoise determines how much that stage is allowed to rework the latent; higher strengths permit larger changes. A value such as 0.45 is not 45% visual sharpening. passes repeats refinement, using seed + pass_index; latent_upscale exits after the spatial-only operation. Multiple passes cost additional time and can accumulate unwanted changes.

sampler/scheduler configure this stage independently. Optional sigmas overrides its applicable schedule. refine_model can supply a compatible alternative H3 model; when disconnected, the active shot model is reused. The stage still uses the shot's effective conditioning and guidance. Do not connect an arbitrary image-model checkpoint merely because its socket also says MODEL.

Upscale models and memory controls

target_width/target_height describe output pixels; latent spatial dimensions derive from the video VAE's factor of 16 and patch-grid alignment. latent_upscale_model=interpolate selects the interpolation fallback. Installed learned H3 upscalers must match the latent representation; they are different from stock RGB image upscalers.

enable_tiling divides spatial work; tile_count and tile_overlap apply to the sampling-tile path. Overlap adds redundant coverage to blend boundaries. enable_latent_chunking requests temporal chunking for supported upscaling engines. Tiles/chunks reduce particular intermediate working sets, while the full input/output latent and model can still consume substantial memory.

Continuity prefixes require special handling: the global adapter carries the native audiovisual phase and can preserve a pinned prefix while allowing a soft seam region to refine. Replacing a continuation noise mask with a generic full-denoise mask can break the join; the pack handles this inside the backend rather than asking you to edit masks manually.

Example and diagnosis

  1. First approve an ordinary shot without refinement.
  2. Connect Refine in mode refine, one pass, 3 steps, denoise 0.45. Compare the same seed and prompt.
  3. For actual enlargement, change to upscale and set an aligned canvas such as 1344×768. Watch memory before trying 1792×1024.
  4. If identity or motion changes too much, reduce denoise/passes or disable the stage. If seams appear, compare overlap and the unrefined baseline.

Use the pre_refine cache stream in Project Video Export to compare the initial sample with the final decoded result. A higher-resolution output does not prove that additional details are correct.
