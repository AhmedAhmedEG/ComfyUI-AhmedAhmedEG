Architecture, data and execution

Understand what the pack exchanges between nodes, when work executes, and where a finished take lives before changing advanced stages.

Three distinct model systems

H3 generation needs a diffusion family, MiniMax CLIP and video/audio VAEs. FL2VA handles text and endpoint-keyframe tasks; REF2VA handles reference/video-editing tasks. A Turbo LoRA modifies its intended family and has its own recommended schedule. H3 SLA Attention is an external model patch from plaguekind-nodes, not a second diffusion generator in this pack.

H3 latent upscalers and the Semantic Bridge student are optional enhancement weights with their own architectures. A stock RGB UPSCALE_MODEL belongs to Pixel Upscale. FaceRefine additionally needs face detection weights. These files cannot be substituted for each other because their dropdowns all happen to contain model names.

Prompt Forge optionally uses a separate language/vision model, either local or accessed over HTTP. Its task is drafting authoring text. It does not replace MiniMax CLIP or the video diffusion model. A local LLM may use GPU memory alongside H3; an HTTP provider runs on the configured provider endpoint.

ComfyUI execution and the Master pipeline

ComfyUI evaluates graph dependencies leading to output nodes. A cable makes a dependency; moving a box on the canvas does not change that dependency. The starter's left-to-right order makes the topology visible: loaders/Boolean/integers → patches/selectors/Settings/Reference Pack → Master → Smart Preview. Collapsed stock selectors hide redundant connected widget displays while their cables retain the actual selection logic.

Within the Master, shots are processed in timeline order. Task selection determines which family is requested through lazy inputs. Native task conditioning converts text/reference media into embeddings and a prepared audiovisual latent. Motion Context or Latent Carry adds appropriate predecessor information. First-pass sampling, optional progressive SelfLift, optional Refine, VAE decoding and decoded face/color/audio work are separate stages. Connecting several enhancement packs does not merge them into one generic quality slider.

Frame grids, latent grids and time

The generation time base is 24 video fps; native audio latent timing and decoded audio sample rates are separate. H3's valid video lengths follow F=5+17k. The standard upward alignment for a requested F is 5+17×ceil((F−5)/17), with a minimum of five. Requested 48 frames therefore align to 56; requested 120 align to 124. Read actual delivered frame_count/fps when computing duration.

The implemented H3 video latent uses a spatial VAE reduction of 16 and temporal grid conversion from core/config.py; video channels and native AV representation must match the H3 model. Transformer 2×2 latent patchification requires output pixel dimensions aligned to 32. Context lengths such as 22 refer to decoded video frames, not latent time cells or LLM tokens.

A continuation can include a context prefix inside the sampling interval. That prefix is removed from the delivered sequence according to saved seam metadata. A source-video edit instead preserves its explicit visible source coordinates. Export must apply the correct metadata once; adding an arbitrary extra trim to “fix” the grid can delete real action/audio.

Authoring JSON versus execution/cache state

{
  "version": 2,
  "project_id": "my_scene",
  "clips": [{
    "id": "clip_1", "name": "Opening", "type": "REF2VA",
    "duration": 5, "prompt": "...", "seed": "123",
    "selected": true, "validated": false,
    "ref_ids": ["image_1", "p2_audio_1"]
  }]
}

This illustrates authoring fields; it is not a complete replacement for the editor's serialized schema. Seeds can be stored as decimal strings to preserve the full unsigned 64-bit range through JavaScript JSON. Stable project/clip IDs associate authoring with the server manifest. Pool execution rows additionally carry real tensors; those tensors are not embedded in the lightweight workflow JSON.

The cache stores take identities, sampled latents, decoded frames/audio, optional pre-refine streams and seam/fingerprint metadata. A preview MP4 is a derived viewing copy. A workflow JSON describes nodes/cables/widgets. A media/project archive carries its documented authoring/media content. A checkpoint loads server-generated state. None of these automatically installs missing models, dependencies or the entire remote environment.

Three caches with different purposes

Master take cacheCompleted project/shot generations persisted on the server.Reuse needs compatible effective-input fingerprints, approval/selection rules and complete readable media/latent data.

Chained take fingerprints include predecessor dependencies. Changing an approved predecessor can invalidate later takes even if their own prompt text stays unchanged. A validation flag is not an instruction to ignore model/media changes. Inspect status and server diagnostics to distinguish a generated, cached or original-source action.

VRAM, host memory, storage and network are separate budgets

Model weights, attention activations and latent sampling consume device memory. Decoded IMAGE/AUDIO batches and encoded intermediate handling can consume host memory. Persisted takes and exports consume disk. Preview/downloads consume network bandwidth. Lowering preview resolution can reduce transfer without solving a GPU sampling failure. Spatial tiling can reduce a particular activation working set without eliminating model weights or the output batch.

Shorten the shot and lower the generation canvas for a first failing render, then compare optional stages one at a time. A learned upscale, FaceRefine and local LLM each add their own work. Use cached per-shot final export for a long sequence instead of re-running the Master just to encode an existing project. Keep cache backups when you depend on continuation latents.

Implementation map and verification boundaries

nodes/ contains public schema/dispatch classes. core/executor.py interfaces with native H3 conditioning and decode. core/sampling.py and advanced_sampling.py adapt sampler paths. continuity.py and vendored continuation code manage seam state. cache_manager.py/project.py manage persistent take/authoring state. references.py/source_media.py handle media selection/edit ranges. preview.py and the separate player provide revision-addressed viewing. forge.py/local_llm.py implement constrained draft providers. Vendored engines remain internal algorithms rather than duplicate public nodes.

Workflow validation checks types, links, installed models and graph health. Backend tests exercise contracts with lightweight substitutes; frontend harnesses exercise widget migration, drag, token/reference selection and player lifecycle. These checks do not substitute for a GPU quality benchmark on your model files. Reproducibility requires the actual models, provider versions, media and execution settings as well as a seed.
