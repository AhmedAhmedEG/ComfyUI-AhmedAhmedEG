Export existing takes one shot at a time

This output node reads a project's cached shots, encodes individual files and assembles a disk-backed native VIDEO. It does not ask H3 to generate every shot again. Compared with the Master's full decoded IMAGE output, per-shot export limits the decoded project data needed at one time, although each individual shot still needs memory and encoding work.

timeline is a force-input STRING containing project_state/timeline JSON. Its project_id takes precedence over the node's project_id fallback. Connect Master.project_state for an ordinary graph, or supply a saved valid state when exporting a preexisting project. In a graph where the Master is upstream, ComfyUI may execute that Master first; a disk-cache exporter does not automatically stop upstream generation scheduling.

Which cached representation to export

streamUse
finalThe saved final shot result, including applied enhancement stages.
pre_refineThe saved result before the latent refinement stage, useful for comparing whether refinement improved the sample.
original_sourceThe original source-video range for source-editing shots, useful for comparing an edit with its input.

A stream must actually exist for the chosen shots. It is not created by typing its name. selection=all includes the timeline's available eligible shots; selected follows each shot's selected flag. No matching exportable shots is an error rather than a one-frame replacement movie.

Seams, canvas normalization and FPS

The exporter consults saved continuity metadata to remove applicable prefix and previous-tail overlap, preventing duplicate context in the assembled sequence. Audio is trimmed to match and processed with configured gain/fade behavior. Mixed shot dimensions are normalized to the first export canvas using the implemented fit/pad path.

fps is export playback rate. When it differs from 24, this node resamples frame indices so the approximate duration is preserved. It does not run optical-flow interpolation or change H3's generation FPS. For example, a 24-frame one-second take exported at 30 fps gets approximately 30 output frames, some duplicated, rather than simply playing the original 24 faster.

export_individual_shots controls persistent individual-shot files versus intermediate files. filename_prefix names their output group and assembled file. Per-shot encoding uses the implementation's H.264/MP4 path and the final assembly uses FFmpeg concat with stream copy; therefore FFmpeg availability and compatible intermediate files matter even though no diffusion model is used.

Native VIDEO and shot-file metadata

video is a ComfyUI VIDEO backed by the assembled file, suitable for native video nodes. shot_files_json describes individual exported files. It is not the image tensor batch and is not a portable copy of the entire generation cache. A workflow referencing a project_id without copying its cache to another server will fail to restore unavailable shots.

Master.project_state ─→ Project / Shot Video Export.timeline
stream = final, selection = all, fps = 24
video ─→ native video processing/saving
shot_files_json ─→ inspect individual export descriptors

If a shot is missing, inspect its cache completeness and selected stream. If a join repeats frames, compare context_prefix/previous_trim metadata with the authored sequence rather than adding an arbitrary second trim. If assembly fails after shot files are written, inspect the FFmpeg concat error; generation need not be repeated to diagnose an encoding problem.
