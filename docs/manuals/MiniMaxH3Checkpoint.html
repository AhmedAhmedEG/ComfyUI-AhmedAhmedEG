A saved generated take, including its working state

A checkpoint here is a cached take from this pack, not a diffusion-model weight file. The node loads decoded frames, audio and the sampled H3 latent. Its continuation output also records project_id, clip_id and generation/take identity. Connect checkpoint to Master.continuation when deliberately continuing a selected result, or use the separate outputs for inspection/export.

project_id chooses the server-side project cache. clip_id chooses a shot within that project. take_id=latest loads the shot's current manifest entry. A specific take_id looks up the recorded take and verifies that it belongs to the requested shot. It does not search another project merely because an identically named file exists.

Change detection and completeness

For latest, IS_CHANGED tracks the cached latent file's modification time so a newer take can trigger reevaluation. A specific take uses that explicit identity. The loader requires readable latent, frames and audio; it raises an error for a missing/incomplete checkpoint. Loading a workflow JSON on another server cannot restore these files automatically.

Save the take identity when reproducibility matters. Latest is convenient during iteration, but it intentionally changes when another take becomes current. A saved-take selector and the Master’s validated flag are separate concepts: selection chooses a take; validation requests reuse only when effective inputs/fingerprints are compatible.

The checkpoint remains server-side tensor/cache state. A preview MP4 has neither the complete latent nor its continuation masks and cannot stand in for a checkpoint. Keep the cache when moving/restoring projects that depend on continuation.
