Generation mode: what a Run actually does

This is a scheduling decision for the Master, not a video model and not a playback setting. The node returns a configuration dictionary. When you press ComfyUI Run, the Master reads that dictionary, walks the ordered shots, resolves references, builds conditioning, then either samples a new take or restores usable cached data. The separate Smart Preview reads completed take caches afterwards.

Worked example: you have shots A, B and C. In Next shot, a first run generates A. Inspect it and validate it. A second run can restore A and generate B; a third can restore A and B and generate C. If A remains unvalidated, another run may sample A again. Next shot means one newly sampled shot per execution, not “automatically advance the playhead.” Changing A's effective inputs invalidates its matching cache, and chained successors can also become stale.

The Master’s Generate selected shots checkbox adds a separate eligibility restriction. An unselected shot must have a usable matching cache or a supported original-source range; it is not silently replaced with an empty placeholder. “All shots” does not override that explicit selection restriction. The player’s Latest clip/Full video choice affects downloads, not this scheduling.

Continuity: what information crosses the seam

Independent shots each begin without the preceding shot’s generated context. A chained shot receives information from its predecessor to encourage the same motion, subject and sound to continue. This is conditioning and sampling state, not merely a crossfade between finished MP4 files. A context prefix can be sampled or pinned inside the new latent, then removed from the delivered sequence so the viewer does not see the same time twice.

Continuity applies only when the current shot permits chaining and a usable predecessor exists. Image Inpaint and explicit video-source editing follow their own rules. I2VA with an explicit opening image uses that image; L2VA is a closing-frame task. REF2VA can receive previous visual/audio material when local references are absent, while multi-frame context is handled separately. See the Master’s mode and reference rules rather than assuming every task uses the same seam mechanism.

Context length is a count of video frames

context_length is measured in decoded video frames at 24 fps. It is unrelated to an LLM token limit and is not a number of diffusion steps. The choices follow the H3 temporal grid: 5, 22, 39 and 56. Their durations are approximately 0.208, 0.917, 1.625 and 2.333 seconds. The Master limits the requested context to the available tail and aligns it down; a short predecessor cannot supply 56 real frames.

For a five-second continuation with 22 context frames, the model works on an aligned sequence containing both the visible new material and its context prefix. The delivered frames have the prefix removed during assembly. Consequently, timeline duration, native aligned generation length and final delivered length are related but not interchangeable. A longer context consumes more computation and can preserve unwanted previous motion. Begin with 22 for an ordinary continuation, 5 for a lighter handoff, and Independent for a hard scene cut.

Resolution, sampling and reproducibility

width and height define the generation canvas. H3's video VAE reduces spatial dimensions by 16 and the transformer patchifies 2×2 latent cells, so the canvas uses multiples of 32. A 960×544 frame contains 510,240 pixels; 1344×768 contains 1,032,192, approximately twice as many. Increasing both dimensions by a factor of two creates four times as many pixels, although exact memory and runtime depend on attention, frame count and model offloading.

frame_rate is fixed to 24 for H3 generation. Changing an encoder's FPS later does not change the time basis of reference guides. Use Output Processing for a deliberate resample or retime. Requested durations are aligned to 5 + 17k frames; for example, 48 requested frames become 56, or about 2.333 seconds, in the standard upward alignment path.

steps counts diffusion sampling iterations. It is not the clip duration. Use the step schedule intended for the selected model/LoRA; the starter's Boolean drives a stock integer selector, choosing 25 base steps or 8 Turbo steps through this node's connected steps input. Edit the two integer nodes to change those presets. A connected input is authoritative even if the disabled widget still displays a saved fallback value. This is a global step choice; turn Turbo off when running a family for which that LoRA is not intended.

cfg controls classifier-free guidance passed to the sampler. The starter uses 1. A larger number does not mean higher resolution or guaranteed stronger adherence; it changes the balance of conditional/unconditional guidance and can create artifacts. sampler chooses the numerical integration method and scheduler chooses the noise schedule. Their choices come from installed ComfyUI. Keep euler/simple while establishing a baseline. If external SIGMAS are connected to the Master, that supplied schedule takes precedence in the sampling path; do not treat a dropdown change as proof that the external schedule changed.

shift_video and shift_audio are separate H3 noise/sigma shifts. They alter the audiovisual sampling schedule; they are neither audio volume nor a time offset. The standard starter uses 12 and 3. Changing them changes the effective generation inputs and may invalidate a take. seed initializes sampling noise. Keep it fixed for comparisons, but also keep model, references, conditioning, algorithm and dimensions fixed: a seed alone does not reproduce a result across arbitrary changes. Per-shot seeds and seed-advance behavior can override the baseline.

Configuration precedence and an external-input example

settings_optional carries a previous configuration. This node copies it and overwrites matching fields with its own canvas/sampling values, retaining other incoming keys. The Master uses the resulting config as its baseline; per-shot options and active timeline canvas controls can override relevant values. SelfLift, Refine and FaceRefine are separate configuration packs connected to their own Master sockets.

To connect a different external integer in your own graph, convert the steps widget to an input using ComfyUI's widget context menu, then connect an INT output. Removing the connection restores ordinary widget use. Do not connect the Boolean itself to an INT steps input.

When a control is missing or a setting seems ignored

A saved graph stores widget values, while the running server advertises the node definition used to create those widgets. A browser using an old definition can lack a newly added control. Current Settings must expose Generation mode above Continuity mode. Refresh the browser after an update, then create a fresh Settings node or load the current starter. This pack also migrates legacy positional/named settings, including workflows without the frontend seed-control widget. Keep your existing graph saved before replacing nodes.

If steps appears unchanged, inspect its connected cable. If a run repeats an earlier shot, inspect validation and cache matching rather than changing Continuity mode. If Conditioning only produces no movie, connect an external sampler and decoder or return to Next shot/All shots. If a first shot ignores context length, that is expected when no predecessor exists. Verify status and the server log when distinguishing generated, cached and source actions.
