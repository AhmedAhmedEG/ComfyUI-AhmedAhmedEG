Review before changing authoring state

This node takes a timeline STRING and a validated MMX_PROMPT_DRAFT, then either returns the unchanged timeline or a new authored timeline. apply=false is a no-op gate. apply=true checks that the draft's context_key matches the supplied timeline, reparses its proposed shots and applies the chosen policy. It does not run diffusion or approve completed takes.

The explicit gate is useful in graph-based automation: generate a draft, inspect the review JSON, then deliberately enable application. A stale context error means that the timeline changed since drafting; obtain/review a fresh draft rather than deleting its fingerprint field.

Replace and Append

policy=replace uses the draft as the new ordered shot list. Where a draft position corresponds to an existing shot, the implementation deep-copies that shot's stored properties, then replaces allowed drafted fields. References/model overrides can therefore survive a prompt rewrite, while the shot is marked unvalidated because its effective generation instructions changed. If the draft has fewer shots, the resulting authored list has fewer entries.

policy=append retains the current list and appends newly created proposed shots. New entries receive IDs/names where needed and are selected but unvalidated. Appending text does not automatically assign Reference Pack items to those new shots.

timeline A + draft for A + apply=false → unchanged A
timeline A + draft for A + Replace    → proposed list, unvalidated
timeline A + draft for A + Append     → A followed by proposed shots
timeline B + draft for A              → stale-context error

Using the resulting STRING safely in a graph

The output is serialized timeline authoring JSON. Feed it to a compatible authoring/import path or connect it to the intended advanced timeline input. A STRING output is not proof that a node can accept arbitrary JSON: check the receiving node's contract. The ordinary Master editor already manages its timeline_data widget, so avoid accidental competing storage/edit paths.

Review task-family changes as well as prose. Replacing T2VA with REF2VA creates a different model/reference requirement even when existing fields survive. The parser rejects unsupported draft fields instead of letting a language model alter assets or approval. Inspect the new sequence and reference assignments before rendering a long batch.
